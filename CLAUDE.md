# Правила работы с проектом ПрофНавигатор

## Технические требования

- Каждая страница — **один HTML-файл**: весь CSS и JS внутри, никаких внешних библиотек, фреймворков и CDN
- Иконки — только inline SVG
- Шрифты — системный стек: `-apple-system, BlinkMacSystemFont, 'Segoe UI', system-ui, sans-serif`
- Никаких внешних зависимостей — страница должна работать без интернета

## Дизайн-система

```
Фон:        #070e1b (тёмно-синий)
Карточки:   #0d1726
Акцент:     #f97316 (оранжевый), #fbbf24 (янтарь)
Вспомогач.: #0ea5e9 (голубой), #10b981 (зелёный)
Текст:      #f1f5f9 (основной), #94a3b8 (приглушённый)
Граница:    rgba(255,255,255,0.07)
```

- Тёмный фон, светлый текст, главный акцентный цвет — **оранжевый**
- Кнопки: градиент оранжевый → янтарь, с пульсирующей анимацией `box-shadow`
- Карточки: glass morphism, `backdrop-filter: blur`
- Анимации: плавное появление при скролле через IntersectionObserver

## Адаптивность

- Mobile-first подход
- Контент должен отлично выглядеть на экранах от 320px
- Основные breakpoints: `680px` и `420px`
- Кнопки и текст — удобного размера для нажатия пальцем

## Стиль текста

- Простой и дружеский язык — как разговор с умным другом
- Никакого канцелярита: не «осуществить выбор», а «выбрать»
- Обращение к подростку на «ты», к родителям на «вы»
- Короткие предложения, конкретные формулировки

## Процесс работы

- **Перед созданием нового файла** — сначала описать, что планируется сделать: структура, секции, логика. Только после подтверждения — писать код
- Коммитить после каждого завершённого файла или значимого изменения
- Пушить на GitHub после коммита

## Служебные файлы — поддерживать актуальными

Эти файлы ведёт Claude автоматически на протяжении всего проекта:

- **`CHANGELOG.md`** — обновлять после каждого значимого изменения: что добавлено, что изменено
- **`IDEAS.md`** — записывать сюда любые идеи, которые звучат в разговоре (Павел или Claude), даже сырые
- **`CONTENT.md`** — добавлять тексты каждой новой страницы; обновлять при правке копирайтинга
- **`PLAN.md`** — отмечать `[x]` выполненные пункты; добавлять новые задачи по мере появления
- **`SPRINT.md`** — обновлять в начале каждой сессии: текущие задачи, статус, блокеры
- **`COMPONENTS.md`** — добавлять новый компонент при каждом его появлении в HTML
- **`PERSONAS.md`** — обновлять при появлении новых инсайтов об аудитории или новых сегментах
- **`DECISIONS.md`** — фиксировать ключевые решения (создаётся при первом решении, которое стоит запомнить)
- **`UX-FLOWS.md`** — создать перед разработкой quiz.html; обновлять при изменении пользовательского пути

## Автоматическое управление документацией

Claude самостоятельно отслеживает, когда нужно создавать новые файлы или обновлять существующие. Павел не должен думать об этом — Claude оповещает и делает сам. Правило: сначала оповестить, потом создать/обновить.

## Структура проекта

```
ProfNavigator/
├── CLAUDE.md          # правила работы с проектом
├── project.md         # описание и стратегия проекта
├── PLAN.md            # план развития (чек-лист по этапам)
├── SPRINT.md          # текущий спринт (оперативные задачи)
├── CHANGELOG.md       # история изменений
├── IDEAS.md           # блокнот для идей
├── CONTENT.md         # все тексты сайта в одном месте
├── COMPONENTS.md      # каталог UI-компонентов
├── PERSONAS.md        # детальные портреты аудитории
├── DECISIONS.md       # журнал ключевых решений (создаётся при необходимости)
├── UX-FLOWS.md        # пользовательские пути (создаётся перед quiz.html)
├── METRICS.md         # KPI и цели (создаётся перед запуском трафика)
├── PROMPTS.md         # AI-промпты (создаётся при разработке логики отчёта)
├── landing.html       # лендинг (главная страница)
├── quiz.html          # мини-квиз (в разработке)
├── result.html        # страница результата / отчёта (в разработке)
└── ...
```
